# WP-09 热成像

面向登陆舰 WP-09 USB-C 直连的 Android 应用。安装包使用独立包名，可与原应用共存。支持 Android 7.0 及以上的 ARM64 手机，连接设备需要 USB Host（OTG）。

在 [GitHub Releases](https://github.com/PeterPtroc/WP-09/releases/latest) 下载 `WP-09-v*-arm64.apk` 安装。手机无需安装英睿应用。如果手机上装过本项目的调试版，先备份要保留的数据，再卸载调试版并安装正式版。后续使用本项目正式签名的版本可以覆盖升级。

## 拍摄和测量

应用固定横屏。连接 WP-09 后授予相机和 USB 权限。右上角的 fps 统计实际绘制的新帧。设备协商优先请求 50 fps，实际速度取决于取流模式、手机和编码器。

- **预览与拍照**　XWild_WP09_C 连接后自动读取每个像素的温度。点选画面可读取该帧对应像素的摄氏温度。拍照保存所见测温帧与全部 49,152 个读数。定格后长按右上角状态可导出 CSV。
- **录像**　点“录像”录制逐像素测温视频。录像中点“拍照”保存屏幕刚刚绘制的测温帧，照片在独立线程写入。视频和温度曲线使用同一条 USB 取样时间轴，旧版分批取样录像仍按原有方式匀速回放。
- **测量**　实时画面的高低温、选点和“画面均温”来自同一帧。旧照片、录像若含相机记录的三个参考值，标记和提醒使用原存的高温与低温，“中心温度”显示中心双像素读数。估算的选点温度带有 ≈。超出原存高低温范围的估值在选点下方单列，不计入线、面平均。点侧栏“最高温”或“最低温”可分别开关画面标记，预览和相册共用此设置。点按画面选点，拖出线段或矩形测量，曲线键显示近 30 秒温度或线剖面。
- **定格与校准**　点“定格”保留刚绘制的热像，可测温或拍照。双指缩放和平移，点测温模式支持单指平移放大的画面。点“快门校准”触发相机自身的快门校正。
- **激光**　主界面点“开启激光”，相机确认后按钮高亮并显示“关闭激光”。预览、定格和录像中均可操作。
- **提醒与校准**　“设置 → 高低温提醒”分别填写摄氏阈值，留空可关闭该项。实时画面的高低温越界时显示提示并响一声，回落或回升 0.5 °C 后可再次触发。发射率、单点或两点校准也在设置中。先设置发射率，再用已知温度的参考面校准。逐像素测温画面使用选点附近的有效读数，三点画面使用相机的中心读数。更改发射率会重置现场校准。
- **相册**　断开设备也可打开。点照片或录像查询温度，录像支持播放、拖动进度和逐帧前后查看。“打开文件”可读取从其他设备复制来的原文件及旧版普通照片、录像。Android 10 及以上保存在系统图片或影片的 WP09 目录，较早系统保存在应用外部目录。旧文件仅显示有成像和温度的重叠范围。缩略图、标点、缩放及手指选点也以该范围为界。

各个按钮、状态和错误提示的实际文字见[界面文案清单](界面文案.md)。

## WP-09 V12 测温依据

V12 的 `ir_sample` 在测温输出回调（`0x421538`）处理设备标出的盲元。八个邻点均可用时，它将计数排序，去掉两端后取其余六个的整数平均。随后按行扫描有效的 256 × 192 个无符号计数，严格比较高低，相同计数保留先遇到的位置（`0x421898`）。中心取第 96 行第 127、128 列的计数，先平均并向下取整（坐标从零起）。原厂 Android 库 `thermometrySearch_XWild` 用计数查同帧温度表，测得的热点和任意单像素都可使用 `T(x,y) = LUT[AD(x,y)]`。[V12 固件](https://infiray-1308317278.cos.ap-nanjing.myqcloud.com/firmware/XWild-upgrade-12.img)

逐像素测温使用 256 × 196 的 UVC 流。连接时先用 0x8005 获取原厂预览的参考读数，再用 0x8004 从测温通道 (3,4) 连续读取 16 位像素并做工厂盲元修正。首张测温图与参考曝光的高、低、中心以及热点和冷点原位置核对，允许相邻曝光有 1 °C 的变化。验证成功后才开始显示实时测温。读不到盲元表时，还要求极值位置、计数和中心计数与固件记录完全一致。拍照、开始和停止录像均使用同一已识别的通道，关闭设备时恢复原厂显示输出。

原厂 XWild Android 应用的快门按钮调用 `UVCCamera.setZoom(0x8000)`。V12 将请求送到 `force_ir_dynamic_calib`。机内测温回调在校准标志置位时提前返回（`0x421554`、`0x422a68`），这一帧也绕过下游显示处理（`0x41c584`）。开快门后固件另留 100 ms 稳定时间（`0x423790`）。模式 4 直接复制测温通道的像素（`0x483714`），帧尾的极值和中心可能仍来自先前一次曝光。

点“快门校准”后，预览和录像保留上一张有效画面。自动校准时，应用检查突然变平的场景和不相符的固件统计。手动触发或识别到自动快门后，应用在后台等原厂显示通道恢复，再用其高、低、中心温度和极值位置核对恢复后的首帧测温数据。挡片期间的读数跳过测量、报警和保存，录像保留这段停顿的实际时长。

V12 为红外预览装载独立的调校文件，ISP 提供二维和三维降噪强度控制（`0x427eac`、`0x427f8c`）。手机用完整测温面着色时，先估计相邻行共有的细小偏差，再按本帧噪声抑制平坦区域的颗粒。明显的水平边缘会分开处理。预览、照片和视频共用这套显示处理，选点、极值和文件中的逐像素摄氏值直接取自测温面。

较早版本使用 `0x802f` 导出原始传感器数据，在 (2,8) 裁出相同的 256 × 192 视场。V12 的测温输出已经过机内逐像素校正。旧文件保存的原始读数、8 位显示亮度和三个固件读数，无法唯一恢复整张校正后的温度面。

## 测温文件格式 v1

照片和无声录像都保存完整的 256 × 192 视场。缩放、测量标记和侧栏属于查看界面。系统相册可直接显示彩色 PNG 或播放 H.264 MP4，本软件相册从同一个文件恢复测量数据、现场校准、调色板和温标。分享原文件可保留测温数据，重新压缩图片或转码视频可能移除扩展数据。

- PNG 在 IEND 前写入私有辅助块 `wpTH`，采用标准 PNG CRC。普通 PNG 解码器可跳过该块。 v0.9.3 在它之前附加 24 字节的 `wpFM`。其中首个 int32 表示存储平面中可见的起始列，再依次保存固件冷、热点的两个 int32 索引和最低、最高、中心的三个 float32。缺失索引为 -1，缺失温度为 NaN。
- MP4 在标准视频轨之后追加扩展长度的 `uuid` box，标识为 `29937dbe-8725-4c0a-a712-f577c121b848`。box 内容依次为 32 位版本和帧数、64 位时长（微秒）、每帧 20 字节的索引及各帧记录。索引项包含成片视频轨的 64 位呈现时间（微秒）、相对记录区的 64 位偏移和 32 位压缩长度。每个视频样本恰好有一条记录，可按时间随机读取。 v0.9.3 另写入 UUID 为 `3b9585a9-c6e3-4f41-b252-ede58e9a79c2` 的事件表。其头部为三个 uint32（版本 1、帧数、标志字段的最低位为 1 时启用匀速播放），每项为 int64 原始事件时间（相对首个样本的微秒数）及与 wpFM 相同的 24 字节。未配对测温帧的时间取自该批文件大小应答。
- 两种容器共用 zlib 无损压缩的 `WPT1` 记录，多字节数值采用大端序。52 字节头依次包含魔数、16 位宽高、四个单字节字段（数据类型、调色板、校准标志、保留）、四个 float32（斜率、偏移、显示下限、显示上限）、两个 32 位极值像素索引，以及四个 float32（最低、最高、中心、平均温度）。类型 2 随后存逐行 float32 摄氏读数，查温时再应用所存现场校准。类型 3 在同样的读数后追加固件已处理的 8 位亮度平面。自动显示的类型 3 用 NaN 记录上下限，类型 2 保留有限的逐帧上下限，供旧版读取。类型 1 存 8 位亮度平面并使用同帧三点锚值插值。类型 0 仅有亮度。缺失读数使用 NaN。
- v0.9.4 用 PNG 的单字节块 `wpDS` 和 MP4 的可选 UUID `9ebdf339-8d3a-4524-a156-598f9e29ee65` 保存温标锁定状态。MP4 块在 UUID 后含 uint32 版本 1 和每帧一个字节，0 为自动，1 为锁定。旧文件的类型 2 用原存上下限是否与该帧极值相等判断自动模式。
- v0.9.5 在使用相机逐像素测温输出的 PNG 中加入单字节块 `wpPL`，值为 1。MP4 用可选 UUID `5d099768-a218-4140-93be-dd598bf84407` 保存来源，uint32 版本 1 后每帧一个字节，1 为固件测温输出。缺失该来源标志的旧逐像素记录按原始估温读取。

## 实机取样

如果接入后无法出图或测温，把 WP-09 朝向桌面或墙面，长按右上角连接状态，选择“导出 ZIP”。文件含 USB 状态和可读取的一帧原始热像。连接支持逐像素测温的设备时，`capture.hid_reader` 记录当前使用的读取方式（`queued` 或 `sequential`）。发送该文件可用于分辨连接问题、普通预览帧和可解码的辐射测温帧。

## 构建与验证

使用 Android SDK 35、NDK 27.1.12297006、CMake 3.22.1 和 JDK 17 或 21。Gradle 直接打包 `app/src/main/jniLibs/arm64-v8a/` 下的四个库，构建无需原 APK。正式版通过 R8 裁剪未使用的代码和资源，本地热像处理库只导出 JNI 入口。

`libusb100.so`、`libuvc.so`、`libjpeg-turbo1500.so` 和 `libthermometry.so` 取自英睿 `INREII-release-87.apk`，用于连接设备、读取热图和解码测温数据。原文件的 SHA-256 为 `a26dc91e7f80ab4628edf5701b19caafaf3f1a7d2a8cbc64bd37ba8ed9efa558`。[英睿官网下载页](https://inreii.com/service/infiray-app/)

```sh
./gradlew :app:assembleDebug :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
```

测试覆盖发射率与现场校准、点线面统计、缩放后的选点、锁定色阶、提醒、无损 PNG 回读、MP4 视频样本与温度索引对齐及相册逐帧查看。可在调试版应用缓存中放入实机的八帧原始转储 `wp09-dump.bin` 和同次预览参考帧 `wp09-reference.bin`，通过 `adb shell am instrument -w -e replaySeconds 30 org.thermal.wp09.test/org.thermal.wp09.ThermalSmokeTest` 以 50 Hz 回放并统计实际绘制和编码帧数。USB 实际取流帧率和绝对测温精度需要实机测量。

## 自动发布

推送 `main` 或向 `main` 提交 Pull Request 后，GitHub Actions 运行 Android Lint、编译测试 APK 并上传调试 APK。更新 `app/build.gradle` 中的 `versionCode` 和 `versionName`，将版本提交推送到 `main`，再推送与 `versionName` 一致的 tag。比如 `versionName` 为 `0.7` 时：

```sh
git tag v0.7
git push origin v0.7
```

工作流会校验 tag 和 APK 版本，签名后把 ARM64 安装包及 `SHA256SUMS.txt` 发到 GitHub Releases。发布依赖两个 GitHub Actions Secrets，`WP09_SIGNING_KEYSTORE` 为 Base64 编码的 PKCS#12 密钥库，密钥别名为 `wp09`，`WP09_SIGNING_PASSWORD` 为密钥库密码。保留签名密钥备份，以便后续版本能覆盖升级。
